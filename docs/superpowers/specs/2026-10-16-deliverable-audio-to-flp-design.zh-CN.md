# Suno 音频到可交付 FLP：持续目标与产品设计

状态：目标已建立，用户已确认“可编辑音符与分轨，质量达标后交付”；以下完整设计
待用户核对。本文定义最终交付门槛，当前功能完成情况以路线表和实际证据为准。

## 最终目标

Windows 用户在 GUI 中选择一首 Suno 音频，不必自行提供 MIDI、编辑 JSON 或操作
命令行，即可自动获得新的、可打开和继续编辑的 FL Studio 工程。工程包含分轨音频、
可编辑的主要音乐声部音符、速度／拍号／结构与可发声音源，同时生成试听和质量报告。
音色允许近似，质量通过验收后交付。当前已有的官方 MIDI 可作为可选高保真输入，
但音频单独输入必须成为正式路径。

持续迭代直到所有发布条件满足。测试数量、CI 通过、模型产生 MIDI 或写出 FLP，
均不能单独代表目标完成。任务阻塞时保留原因和证据，继续不依赖该阻塞的工作。

## 用户决定与工程默认选择

用户已决定：音频输入、可编辑音符与分轨、质量达标、最终 GUI、持续迭代，以及
使用分支／PR 并在门槛满足后自动合并。

工程默认选择：Windows 11 x64 优先，首个宿主配置为已固定的 FL Studio
26.1.7.5654；沿用 Python 核心，GUI 候选为 PySide6。具体 GUI、解码器、分离和转写
组件在接入前独立审计许可、运行时、精确版本／提交、模型权重哈希、下载来源、
分发条件及本机表现，未审计不进入发布包。GUI 候选不是已固定的运行依赖。
默认本地处理，无账号、无私有音频上传；首次模型安装是单独可见的准备步骤。

V1 音频范围：WAV、MP3、FLAC，单声道或双声道，最长 10 分钟；解码输出统一为
明确采样率的 PCM，保留原文件哈希、原采样率、解码／重采样配置和时间换算关系。
采样率及声道不受支持、文件损坏或超过资源预算时，明确失败，不截断后宣称成功。
MIDI 可选输入保持现有 Type 0/1 PPQ 支持边界。

## 成品内容与使用流程

```text
选择音频（可选已有 MIDI）→ 检查环境／输出位置／模型
→ 分离与音乐分析 → 转写与编排 → 生成新 FLP
→ 独立重读／宿主重开与渲染 → 自动质量检查 → 展示结果与试听
```

默认交付是一个新目录：`project.flp`、所需的 `audio/`、可编辑结果的 `midi/`、
`preview.wav`、`report.json`、`provenance.json` 和简短使用说明。路径可移植，包内
引用可验证；移到新的目录后仍能打开，不能依赖开发者的绝对私有路径。
专有插件、FL Studio、后端和无分发许可的音色／模型不随包复制。必须外装的依赖
在 GUI 和报告中明确列出；缺失时不能把静音工程标为成功。

默认播放模式为“可编辑重建”：生成的 MIDI 声部发声，原曲和分轨参考组静音，
避免同一声部叠加。`preview.wav` 必须来自这个模式，不能用原分轨掩盖转写错误。
另提供 `reference-preview.wav` 供试听原时序分轨，界面支持互斥切换；两者有独立
路由及状态记录。人声的 MIDI 使用明确的近似音色，原人声分轨保留为可切换参考。
音乐试听验收必须听 MIDI 重建版本，不能只听分轨版本。

可编辑范围为检测到的主要 pitched 声部、鼓点和分轨编排；人声至少提供原时序的
独立音频及主旋律音符。复杂和声／音色的推断单独记录置信度。原混音可作为参考轨，
但不会用仅装入整段混音来替代可编辑音符的验收。分轨间的“其他”混合声部必须明确
标识，不虚构已经分离出独立乐器。

GUI 包含输入／输出选择、环境检查、可理解的阶段进度、取消、恢复、历史任务、
结果试听和质量问题定位。主线程不执行模型或 DAW 长任务。设置只暴露音质、运行
资源等用户能理解的选项；事件编号、内部字段和后端路径放在可展开诊断中。
先做真实作业驱动的薄界面，未实现阶段显示阻塞，不制作模拟成功的进度条。

## 架构和数据权威

```text
GUI / CLI
   └─ application job service / persistent state / cancellation
       ├─ input identity + decode
       ├─ isolated separation / transcription / musical analysis adapters
       ├─ evidence-bearing estimated arrangement OR source-faithful MIDI arrangement
       ├─ explicit instruments / source-channel routing
       ├─ gated FLP writer + bounded background host adapter
       └─ independent replay / render / quality assessment / publication
```

复用 `core`、`arrangement`、`pipeline`、`flp_builder`、`validator` 和
`integrations` 的向内依赖边界。GUI 和 CLI 使用同一作业服务，不能分别实现音乐
处理逻辑。模型和不兼容运行时留在独立进程，凭固定版本清单调用，不污染核心环境。

两种权威必须区分：已有 MIDI 的音符、全部事件、源通道与精确坐标保持原样，沿用
现有严格证据和阻塞；只有音频时，速度、节拍、音符和角色属于推断，保留音频时间
坐标、模型／参数／置信度及每次派生记录，不能标作源 MIDI 或精确转录。
从音频估计时允许算法产生估计结果；不能借此放宽已有 MIDI 的零损失要求。

写入门槛按用途区分：格式完整性、当前文件身份、合法依赖、独占输出、可发声路由、
稳定宿主／重开／渲染及对实际使用字段的验证，对所有路径都适用。已有 MIDI 的
精确速度标量、源通道和控制送达只要输入含有相应内容就必须满足；不能改标为推断
来规避。只有音频的估计路径没有源 MIDI 控制可丢弃，可用经单独验证的时间／音源
配置和明确误差界限；它须有新的独立资格证据，不能升级旧阻断计划的状态。
crop/flag 等限制适用于使用这些字段的候选；不用这些特性的、新的普通字段原型
可单独取得资格，旧六份实验和原模板仍保持原有状态。既有严格 MIDI 用例未解决
时明确为不支持，不把它们算作新音频模式已通过的回归样本。

每个作业保存输入身份、固定模型／插件／宿主身份、参数、每阶段输入输出哈希、
失败和重试记录、质量评估及最终产物身份。恢复只复用身份匹配且完整的阶段；
变更输入、模型、参数或依赖会使相关缓存失效。结果独占发布，失败不留下“完成”标记。

作业状态为 `queued/running/blocked/failed/cancelled/succeeded`。只有自动交付门槛
全部通过才允许 `succeeded`；低置信度或缺失前提进入 `blocked` 并给出理由。
软件版本的最终发布另外要求人工试听和真实环境验收，不要求每位用户的每次作业
都等待开发者批准。GUI 可以展示未通过的候选，但必须明确为不可验收候选。

无真值单曲的 `succeeded` 仅表示“已通过当前固定质量配置的自动检查”，不表示已
证明每个音符正确。配置必须属于已通过发布基准的模型／支持范围，包含经独立校准集
校准的置信度／异常阈值、信号有效性、时序和重建检查；每项阈值、校准版本及规则
在模型资格认定前固定，缺少任何必需规则即阻断，不能使用模型自称准确率来通过。
每份报告同时标明 `ground_truth_metrics=unavailable`、
`musical_correctness=not_proven_per_song` 和 `human_review=not_performed`。
超出支持范围、低置信度或硬门槛失败的作业不能自动成功。用户可试听并导出明确
标识的候选，或记录 `accepted_by_user`；这个记录不能改变自动检查失败或冒充 F1。
发布质量保证限定为下面已固定曲库、资源环境和失败拒绝策略，不承诺任意混音的
逐音符精确反演。该操作性验收政策是工程提案，随完整设计交用户核对。

## 质量门槛

下面数值是首版工程验收目标，不是现有成绩。阈值和测试集在运行前固定；不得为了
使当前结果通过而降低阈值。改变发布质量政策需要记录理由并由用户确认。

| 层次 | 发布必须满足的门槛 |
| --- | --- |
| 文件与来源安全 | 原输入／基准／旧副本身份 100% 一致；独占输出；无越界路径、缺失引用或私有文件进入 Git/发布包 |
| 既有 MIDI 保真 | 事件次数、顺序、通道、程序、控制、原坐标及分段时钟精确一致；任何不支持的事件或精度问题阻断 |
| 音频转写 | 24 个固定、带真值的片段中有 pitched 音符真值的样本上，onset+offset F1 宏平均 ≥0.80，每个片段 ≥0.70；onset 容差 50ms，offset 容差 max(50ms, 真值时长×20%)；匹配算法版本固定 |
| 鼓与节拍 | 有鼓点真值的片段上，类别+onset F1 宏平均 ≥0.85、每片段 ≥0.75；节拍标签匹配的绝对误差中位数 ≤30ms、P95 ≤80ms；测试无节拍片段时正确声明无可靠节拍 |
| 分轨和时序 | 有真值的分轨重建对齐偏差 ≤1 个解码后采样；含干扰且目标有效的混音片段上，模型分轨相对混音基线的 SI-SDR 改善宏平均 ≥3dB、每片段 ≥0dB；无声／无干扰样本另测信号保真或正确拒绝，不混入未定义指标 |
| 编排与依赖 | 主旋律、低音、鼓和和声的支持范围明确；无缺音源、未报告丢音、误删控制、负时长或尾部截断；AI 推断置信度不能代替独立质量分数 |
| FLP 与宿主 | 当前固定宿主独立重读、打开、另存新副本、关闭／重开及后台渲染成功；无错误对话框、丢插件或意外静音；对照原时钟和期望音频，不凭退出码判断成功 |
| GUI 与安装 | 干净 Windows 11 x64 环境可安装启动，无需预装 Python；中文／空格路径、取消、失败恢复、只读输入和依赖缺失用例通过；长任务不冻结 GUI |
| 效率与稳定性 | 在下面固定硬件／资源配置上，3 分钟基准曲暖运行 ≤30 分钟；记录冷启动、峰值 RAM/VRAM和各阶段时长；同一输入连续 10 次不崩溃、不挂起、不覆盖旧输出 |
| 真实音乐质量 | 6 首 1–5 分钟且来源合法的真实曲目，覆盖稀疏、多轨、鼓、人声及变速；每首自动门槛通过，试听确认主旋律／节奏／结构可用、无明显丢段错位；至少一首来自当前真实歌曲 |

24 个片段由六类各四个构成：独奏钢琴、复音乐器、低音、鼓、主唱、混合编制；
每类两个用于开发、一个用于校准、一个留作发布保留集，合计 12／6／6。
开发集用于方案选择；校准集用于固定置信度／异常阈值；发布保留集在模型、参数、
评分规则和阈值冻结后才评估，不参与选择或校准。三个子集分别统计并满足表中同一
宏平均／单片段门槛，不能用开发集高分抵消保留集失败；若修改方案则旧保留集结果
失效，并须补充新的未参与调参保留集。清单含许可／来源、哈希、真值、评分版本。
静音、损坏输入、长尾、速度变化、同音重叠、鼓通道等另作失败／边界集，不与音乐
得分混合。指标是支持范围的发布门槛，不构成任意歌曲都可精确反演的承诺。

AI 单次作业无真值时，只能检查结构、信号异常、对齐、置信度和模型已通过的能力
范围，不能伪称测得真实音符 F1 或真实分轨 SI-SDR。无法证明质量的输入应明确
要求复核／阻断。不同音色的渲染不要求波形逐样本相同；PCM 相等只用于确实应相等
的确定性对照，音乐质量按固定真值和试听分别判断。

性能参考机为当前已只读确认的 Windows 11、i9-12900K、64GiB RAM、RTX 3070 Ti。
发布基准固定 8 个 CPU 工作线程、作业峰值 RAM ≤16GiB、GPU 预算 ≤6GiB，模型版本
和精度固定；模型下载与初次环境安装单独计时。CPU 备用路径必须功能正确并报告
预计耗时，不冒用 GPU 基准的速度承诺。后续硬件适配不得隐式改变质量阈值。

## 分支、自动合并与持续迭代

执行规则见 [GitHub 开发路线](../../GITHUB_WORKFLOW.zh-CN.md)。`main` 是通过
代码门槛的集成分支，发布标签另受上述宿主和音乐质量门槛保护。每个增量从最新
`main` 建立 `codex/<milestone>-<slice>`，一个 PR 只解决一个可验收的问题。
独立审查绑定完整 head SHA。当前提交所有必需 CI 完成、无未解决问题且主线已同步
后，才使用固定 SHA 执行 squash 自动合并；不提前排队等待 CI。任何新提交使旧审查
失效，先取消仍排队的自动合并，再对新 head 审查、清单核对和完整检查。命令后若
没有合入，取消排队并检查变更，不能让待审的新 head 自动合入。不以管理员权限
绕过，不自动合入未经审查的外部分支。

当前仓库为单一维护者，GitHub 的批准人数设为 0，独立代码审查仍是执行规则；
不能把同一维护者凭据提交的自我批准冒充独立 GitHub review。检查门槛、分支保护
和讨论解决由 GitHub 强制；产品质量由可复核证据和发布验收强制，两者不可混淆。

每轮完成：复现／确认问题 → 最小方案与测试 → 实现 → 当前输入复验和文档
→ 独立审查 → PR／CI → 自动合并 → 更新路线与下一个切片。持续目标在实际产品
和全部发布证据齐全前保持未完成；遇需用户决定或外部前提时明确说明，不伪造通过。

## 持续有效的操作边界

允许已授权的有界后台运行；禁止点击、键盘和鼠标操控。开发者对 GUI 的验证先用
无桌面输入的模型／控制器和 offscreen 渲染；真实交互、FL Studio 另存／重开等
不能由现有后台能力完成的项目，保持待验收，不通过模拟测试替代。
不修改原素材、基准、六份实验及随后形成的旧实验副本；每轮新目录、前后身份核对。
不上传私有工程、真实素材、实验或后端；默认 CI 使用原创合成数据，真实验收在本地。
不安装未经许可审计的插件／模型，不更改全局 MIDI 设置，不强制退出用户持有进程。

## 已核对的一手依据

- [GitHub 自动合并](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/configuring-pull-request-merges/managing-auto-merge-for-pull-requests-in-your-repository)：仓库开关与每个 PR 的自动合并分别配置，合并仍需满足要求。

- [Basic Pitch 上游](https://github.com/spotify/basic-pitch)：明确最适合单个乐器；可作逐声部候选，不能据此宣称整曲多乐器转写已解决，模型选型仍需测试。
- [Qt for Python 部署](https://doc.qt.io/qtforpython-6/deployment/index.html)：提供桌面打包路径；实际组件许可、固定版本和 Windows 安装表现需在 GUI 切片验证。
