# M1 Real Job GUI Implementation Plan

> Execute inline using superpowers:executing-plans and TDD; one fresh whole-branch review.
> The user approved the full product design and continuous autonomous implementation,
> review, CI and exact-head automatic merging. No additional design choice changes that scope.

**Goal:** A Chinese desktop workbench creates, checks, resumes, cancels and inspects real
audio jobs without blocking the UI or claiming unavailable conversion capability.

**Architecture:** Pure presentation/actions wrap the existing job service. A single Qt
thread-pool worker per window runs file I/O; only queued result signals update widgets.
Cooperative cancellation is recorded at service boundaries, preserving complete history.
An optional pinned Qt Essentials runtime keeps the ordinary CLI independent of Qt.

**Tech stack:** Python >=3.11, PySide6-Essentials 6.12.0 (QtCore/QtGui/QtWidgets), existing
Pydantic job service. Resolve and retain exact shiboken6 pin/hashes in uv.lock.

**Spec:** [Approved delivery design](../specs/2026-10-16-deliverable-audio-to-flp-design.zh-CN.md).

## Constraints and review focus

- No clicks, keyboard/mouse simulation, desktop automation, host launch or FLP writes.
- New artifact roots only; preserve all original/private/old experimental evidence.
- No inference, model or backend installation. No success or quality assertion from input checks.
- Headless rendering/controller invocation is development evidence, not real user interaction acceptance.
- Long hashing, history loading, environment checks and verification stay off the GUI thread.
- Current source/report changes refuse recovery; broken history remains visible with a useful error.
- Cancel/close during work requests a safe boundary, never kills a thread or drops history.
- CLI without GUI extra remains importable/usable; missing Qt gives a clear prerequisite message.
- Jobs-root changes cannot race an active operation or silently redirect its outputs.
- Worker errors remain visible; stale selected records are reloaded explicitly, never overwritten.

## Visual direction (implementation choices)

Studio workbench, left-aligned and quiet: page #E7EBF0, paper #FFFFFF, ink #152C42,
rail #183549, action #176C89, blocked #8C5B14. Use system Chinese UI font with a clear
26/18/14/12 scale; no bundled fonts. One meaningful visual device: the ordered conversion
route with actual stage states. No fake waveform, decorative cards or progress percentages.

```text
Suno2FLP                 Audio workbench / current capability
jobs folder              source + choose audio + create task
history                  current task / status / explanation
                         actual ordered stages / check, resume, cancel
environment check        expandable provenance + diagnostics
```

Compare alternatives: a marketing dashboard obscures the job; a full DAW editor suggests
unimplemented editing. Use the workbench above, with a compact stage table and persistent
blocked explanation. Keep long paths elided visually with tooltips and exact diagnostics.

## Task 2: Shared GUI actions and presentation

Files: `gui/__init__.py`, `gui/model.py`, `tests/unit/test_gui_model.py`.

Interfaces: `present_job(StoredJob) -> JobView`; `JobActions(root)` with `create(source)`,
`history() -> list[HistoryEntry]`, `load(snapshot)`, `run(snapshot, cancel: Event)`,
`verify(snapshot)`, `cancel(snapshot)`, `environment()`. GUI data never grants writer permission.
History loads only immediate job roots under the selected root, displaying corrupt entries;
no automatic recursive search/private upload. Default root: cwd/workspaces/audio-jobs;
no startup writes. Creation explicitly creates the selected workspace and an exclusive UUID job.
