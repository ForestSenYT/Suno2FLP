# MIDI 事件往返核对与 FL26 后台实验

本批增加独立的 MIDI 事件／精确时钟比较器，并取得选定内部端口与音量响应证据。
真实歌曲仍未生成交付 FLP；精确速度表示、宿主时序、完整程序／控制事件路由和旧模板
验收限制继续阻断。实验工程、厂商预置状态及音频只留本地，不进入 Git 或发行包。

## 可直接使用的只读命令

```powershell
uv run suno2flp compare-midi-events expected.mid host-export.mid --output comparison.json
uv run suno2flp verify-midi-comparison comparison.json
```

第一个命令读取两个 Type 0/1、正 PPQ MIDI，保存独占的新 JSON。比较不同或时钟不确定
时仍保存证据，但退出码为 1；明确相等时为 0。缺失／无法解析的候选文件不会被当作
成功导出。第二个命令重读当前输入并逐字段重算报告；退出码 0 只表示**报告重放一致**，
即便报告的比较结果是不同。任何命令都不会启动 FL Studio、修改 MIDI 或写 FLP。

报告保留两侧完整导入快照、SHA-256、大小、mtime、轨／事件索引、delta、绝对 tick、
原消息及导入诊断。发布前后和重放结束均重新核对输入。已有输出、链接／重解析路径、
与输入重叠的输出和后端目录中的报告被拒绝。

比较分成三项，全部满足且没有导入错误才标记 `equivalent`：

- **事件内容及位置**：只把位置换算成精确分数拍，并从比较键中移除已由位置表达的
  `time`。其余消息字段全部参与比较。重复消息逐个匹配；缺少／新增事件均关联完整
  快照中的地址。跨轨匹配仅用于定位相同内容，不是来源到音源的路由映射。
- **有序轨结构**：按轨位置及轨内原顺序比较完整事件序列。轨重排、拆并、同 tick
  控制消息换序不能因事件集合相同而通过。`note_on velocity=0` 不改写为 `note_off`，
  元事件、结束事件、释放力度、SysEx 和未知元事件也不忽略。
- **时钟**：在两侧速度边界的并集及较长轨结尾，使用 Fraction 累加微秒／拍；报告
  有符号 `candidate − expected` 及最大绝对差。区间内差值为线性，因此这些边界
  可捕获最大误差，也不会让结尾抵消掩盖中途偏差。没有显式速度时应用 MIDI 的
  500000µs／拍默认值。同拍出现不同速度值时不猜执行次序；无效速度也不能用默认值
  替代，这两种情况的时钟结果均为 null。

同拍重复的相同速度值具有确定时钟，但消息本身仍逐条保留。时钟只覆盖报告中明确的
`compared_through_beat`，不预测尾音或插件延迟。解码结果相等不等于文件逐字节相同、
宿主播放相同或原路由正确；报告始终 `receiver_delivery: unverified`、
`writer_eligibility: blocked`、`execution_allowed: false`。

## 后台运行与导出证据

Image-Line 的[命令行导出文档](https://www.image-line.com/fl-studio-learning/fl-studio-online-manual/html/fformats_save_export.htm)
列出音频及 MIDI 导出。本机固定 FL Studio 26.1.7.5654 实测的单文件形式为
`/M"absolute-new-copy.flp"`；M 与路径之间没有空格。此次测试的带空格和目录形式未
产生 MIDI，不能据此宣称其他版本或所有调用形式都失败。

沙箱内进程曾返回 0 却没有任何输出，连先前已验证的 WAV 基线也如此。新副本在获准的
后台环境中正常渲染。失败尝试仍留有记录，不当作格式不支持的证据。后续实验要求
实际输出文件、可解析内容、哈希和输入前后身份；退出码不能代替这些检查。

每个实验使用独立目录、固定哈希的宿主和新 FLP，拒绝已有 FL 进程、限定进程寿命，
必要时只结束自己启动的进程。全部使用 `WindowStyle Hidden`，没有点击、键盘、鼠标
或 UI 自动化；Hidden 不保证宿主绝无窗口。没有安装控制脚本或修改全局设备设置。

## 变速偏差：音频对齐与源事件位置不能混为一谈

两音符对照的第二个音符位于从零开始的 beat=2（96 PPQ 时 tick=192）。第一拍后
120→60 BPM，理论起音为 1.5 秒，
在 44100Hz 下为 66150 帧。沿用[前批的检测方法](FL26_CONTROL_EVIDENCE.zh-CN.md)，
恒速对照起音为理想值加 1 帧。新实验结果：

| 写入控制点的实验位置 | 96 PPQ 起音帧 | 960 PPQ 起音帧 |
| --- | --- | --- |
| 原始位置 | 65921（前批） | 66128（前批） |
| 比原始位置晚 1 tick | 65692 | 66105 |
| 比原始位置早 1 tick | 66151 | 66151 |

120→60→240 对照提前 1 tick 后两种 PPQ 都检测到 49613 帧；120→240 的 96 PPQ
对照提前后为 33076 帧。它们支持**选定案例的调度边界差异**，不证明任意工程的通用
修复。尤其同音符边界上的变速对照，前移／后移并没有移动该音符的起音；总输出长度
又包含尾部行为，不能替代音符时钟。

决定性的反证是同一工程副本的宿主 MIDI 导出：原控制点导出在 tick 96，提前的控制点
导出在 tick 95。提前确实改变了 MIDI 事件位置，而不是一种已经证明无损的内部编码。
因此不把 `tick − 1` 应用于源歌曲，也不放宽“原时序保持”要求。374 个真实速度不能
精确表示成整数毫 BPM 的问题同样没有解决。

## 内部接收与控制响应：已证实范围

官方 [MIDI Out](https://www.image-line.com/fl-studio-learning/fl-studio-online-manual/html/plugins/MIDI%20Out.htm)
和 [Fruity LSD](https://www.image-line.com/fl-studio-learning/fl-studio-online-manual/html/plugins/Fruity%20LSD.htm)
说明发送／接收端口须匹配。仅发现插件或得到非零音频还不够。本批从本机厂商预置
取得状态，只在新的两音符工程中进行正反对照：

| 对照 | 实测结果 |
| --- | --- |
| 发送 1、接收 1 | 非静音，峰值 3984 / 32768 |
| 发送 1、接收 2 | 全部 PCM 样本为零 |
| 发送 2、接收 2 | 与 1→1 的全部 PCM 相同 |
| 匹配端口，中途原生音量归零 | 第二个音符区间全部 PCM 为零 |

这些特定状态中，MIDI Out payload 偏移 24 和 LSD payload 偏移 28 的小端整数修改
通过了端口对照；没有把其他版本或其他字段推断成通用状态格式。原生 REC 音量 12800
与 0 在宿主 MIDI 导出中出现 CC7=127 与 0；这不是整个取值范围的无损映射证明。
原生值 6400 导出为 CC7=64；单独验证的 10000 导出为 CC7=100，且 tick 96 的同值
重复事件仍存在。它们只覆盖这些选定值／位置，不证明任意 CC 或真实歌曲结尾的路由。
程序字段候选变化未取得可区分结果，不予解释或采纳。

默认 MIDI 导出还产生源实验未声明的重复声像、音量、弯音、RPN／程序消息以及末尾
重置；原生 3x Osc 对照也导出类似消息。因此宿主导出是**一个独立观察面**，不是插件
实际接收日志，更不能用于倒推所有原插件状态。新比较器会保留并报告这些新增事件。

目前确认的是单个发送／接收器、两个选定非零端口与选定音量控制的音频响应。尚未
完成真实歌曲 63 个输入／通道组合的隔离、完整程序／bank／CC 顺序、重复事件及
零长度音符的端到端验证。已有源事件、时序和全部保护文件保持原样；没有生成简化或
近似的真实歌曲 FLP 充当交付。

## 运行时、许可与下一步

使用本机已安装的专有 FL Studio、MIDI Out、Fruity LSD 及 Windows DirectMusic/GM
资源；未新增 Python 依赖或第三方实现。预置文件、GM 库、插件和后端均不分发，是否
拥有宿主／素材使用权不由文件存在推定。本机 GM.DLS 位于 Windows `System32/drivers`，
与手册举例路径不同；实验没有复制音色库或改写其路径。宿主可执行文件、实际预置
及 DLL 的身份在私有证据中记录。

仍需找到保留精确速度与事件位置的宿主表示／调度方式，验证明确的多来源路由、
原始程序和 CC 数量／顺序，再通过旧 crop/flag、依赖、重开及试听门槛。此次代码仅
提供可重放的检查，不把局部实验升级成写入授权。

## 验证范围

本批比较器新增 19 项合成测试，覆盖精确 PPQ 转换、速度偏移、事件重复／顺序、
元事件、无效速度、文件身份变化与报告篡改；离线完整流程也加入比较及重放。
本地完整测试为 823 项通过、19 项跳过，其中 16 项需要显式启用的外部后端，
3 项需要本机未提供的链接权限。跳过项不计作宿主兼容性通过。

私有后台记录包含 67 次进程尝试，其中 35 份有效 WAV、15 份有效 MIDI，另有
17 次无输出尝试。152 个受保护文件的哈希、大小和修改时间在前后核对中一致。
六份旧手动验收记录的完整性检查通过，但 54 个阶段仍待执行，写入限制继续阻断。
