# 精确变速与显式 MIDI 路由：当前证据边界

本批增加逐来源／通道的只读路由绑定和重放，并验证选定程序参数会改变宿主导出和
实际音频。真实歌曲仍未生成交付 FLP：精确变速、完整接收链路、原有模板和试听
验收尚未满足。没有移动源速度点、舍入速度或丢弃控制事件来通过检查。

## 可使用的路由检查

```powershell
uv run suno2flp plan-midi-routing performance.json midi-bindings.json --output routing.json
uv run suno2flp verify-midi-routing routing.json
```

输入是已验证的 performance 报告和显式 JSON 绑定文件。例如只有 input 0/channel 2
这一组的来源可使用以下完整配置；多组来源必须逐组列出，工具不会推断缺失目标。

```json
{
  "schema_version": 1,
  "bindings": [
    {
      "source_input": 0,
      "source_channel": 2,
      "destination_port": 16,
      "destination_channel": 2,
      "receiver_id": "receiver-a"
    }
  ]
}
```

通道采用 MIDI 的 0..15 编号，端口为 0..255。接收器名称是明确的逻辑标识，不是已安装
插件或加载指令。配置保留原文档顺序和文件身份；结果按来源组顺序列出目标，保留
完整编码评估、每次控制消息、原始 delta/tick、轨／事件索引和精确换算后的坐标。
完整音符和全部事件仍通过 performance 的源快照及当前源文件重放核对。

检查拒绝缺组、多余组、重复选择器、多个来源占用同一端口／通道、同一端口声明多个
接收器、同一接收器声明多个端口，以及任何通道改写。不同通道可以共用同一接收器
端口；同号源通道跨文件则必须分离。整数不会接受布尔值、字符串或越界端口。

同文件同通道的多个轨保留为同一来源组；重复程序及末尾 CC 不合并。跨轨同 tick
控制组仍保留“不推断唯一执行顺序”的限制。非通道事件、SysEx 和已有时序诊断也
保留在评估内，不因完成通道绑定而消失。

命令只创建新的 JSON，拒绝已有文件、输入覆盖、链接及后端目录；发布前后核对输入。
重放重新读取绑定、performance、arrangement 和当前素材，逐字段重建报告。
成功退出只说明配置检查或报告重放成功；即便 `coverage_complete` 为 true，也始终：

```text
receiver_delivery = unverified
writer_eligibility = blocked
execution_allowed = false
```

旧编码评估中的 destination/status 不会被改写为成功。没有插件加载、MIDI 发送、
后台进程或 FLP 写入入口，也没有更改既有写入器的门槛。

## 程序参数的正向对照

在固定 FL Studio 26.1.7.5654、新建的两音符实验副本和已匹配的内部端口上，
事件 223 的选定插件参数地址 `0x8000` 写入 40 后，宿主 MIDI 导出了程序 39，
包括 tick 96 的同值重复消息。选定值 1 和 82 分别对应导出的程序 0 和 81。
这是本机该 MIDI Out 状态的观察，不是所有插件参数的通用解释。

独立音频对照中，程序 0 与程序 81 的 PCM 不同；从程序 0 切到 81 的对照，其前半秒
与固定程序 0 相同，第二音符区间发生变化。它支持选定程序变化实际影响发声，不能
证明任意值、任意边界的精确发送时刻或接收器收到了所有原消息。

更改发送状态字段和音符颜色的对照并非都改变 MIDI 导出的通道。某个通道字段候选
还导致选定程序的渲染静音；不能把静音解释成已确认的通道语义或正常鼓通道行为。
需要实际接收端的独立证据，不能用“文件已导出”替代。

真实歌曲的绑定报告列出 63 组、66 次程序消息和 66 次 CC7，完整保留重复项。
本地候选使用各输入独立的逻辑接收器／端口并保留源通道；配置检查通过并不证明
这些接收器已建立或互相隔离。逐组后台实验使用合成音符和恒速时钟，控制点只做
精确 PPQ 换算；它们不包含整曲演奏，也不验证真实变速时钟。

63 组中有 57 组完成后台 MIDI 导出。这些组的 120 次源控制，在忽略通道的
类型／数值／精确坐标计数比较中全部有对应项；加入源通道条件后只有 16 次对应。
导出通道与来源不符，且启动／停止消息可能与请求重合，因此这些数字不表示
120 次控制都已送到正确音源，也不构成路由放行依据。

第 58 组超时后，仅在新的字节相同副本上重试一次，仍然超时；剩余 5 组没有执行。
随后已知正向基准的新副本也超时，仅留下 80 字节的不完整 WAV 文件，未形成有效音频。
因此暂停继续启动宿主，不能把这一阶段的失败归因于某个特定源通道。
超时、部分输出及未执行记录均保留，不计为通过；进程退出问题需要独立排查。

官方 [MIDI Out 手册](https://www.image-line.com/fl-studio-learning/fl-studio-online-manual/html/plugins/MIDI%20Out.htm)
区分端口、通道、程序以及播放／停止时的自动发送。实验导出同样含额外启动和末尾
消息，所以不能把该导出当作接收器日志，或从多出的重复项反推某个源事件已送达。

## 不移动事件的精确变速

官方[速度控制说明](https://www.image-line.com/fl-studio-learning/fl-studio-online-manual/html/toolbar_panels.htm)
明确常规微调为 1/1000 BPM。当前已验证的整数毫 BPM 表示不能精确承载真实歌曲的
374 个有效速度变化。增加 PPQ 只改变 tick 网格，不能提高这个速度标量的表示精度；
前批 tick − 1 的方法又明确改变了源事件位置，因此两者都不是已证实的无损修复。

本批另从本机厂商工程读取了既有速度自动化片段和链接结构。该样例声明版本为
12.9.3.321；只把选定结构用于新的最小候选，没有运行或修改厂商原工程。
恒值、变值、通道段位置及通道片段裁剪哨兵的对照均未建立有效的速度响应。
所测音频与恒速基线相同，不能据此讨论该路径的精度，更不能宣称 FL26 的所有
自动化方式都不支持更精确的表示。当前结论是**替代路径仍未验证**。

原音符位置和全部源速度数据保持原样；实验中没有用重新布置音符或预渲染音频来
伪装保留源时序。完整交付仍需要有效的 FL26 速度表示及调度证据、逐来源接收验证，
以及旧 crop/flag、依赖、重开和试听验收。

## 运行与分发边界

所有后台操作都使用固定哈希宿主、独立新目录、实际输出解析及输入前后哈希检查，
禁止已有宿主进程混入并限制每次进程寿命。没有点击、键盘、鼠标、全局设备设置
修改或控制脚本安装。默认测试和新命令完全离线，不需要 FL Studio。

没有新增依赖或复制厂商实现。专有预置状态、厂商工程、音色库、DLL、真实 MIDI／WAV、
完整本地记录及后端都留在忽略目录；公开代码仅实现独立的配置、保真检查和原始
合成测试。读取的第三方格式参考不是新的运行时依赖或宿主兼容性证明。

## 本批验证记录

- 新增 22 个路由合成测试，覆盖完整性、冲突、重复消息、原通道、源事件坐标、
  非通道事件、篡改重放、输入变化以及独占输出；安装后的命令流程包含正反例。
- 全量测试 845 通过、19 跳过；跳过项为 16 个需显式启用的外部后端测试及
  3 个本机缺少链接权限的用例。静态检查、格式、类型、源码包、wheel 和安装流程通过。
- 93 份新实验副本中实际启动 83 次：80 次正常完成，3 次超时；10 份副本未执行，
  对应原批和重试批中相同的 5 组待测来源。正常完成的输出为 67 个 MIDI、13 个 WAV。
  这些是小型实验输出，真实歌曲的交付输出目录仍为空。
- 568 个受保护的素材、基准和旧证据文件的哈希、大小、修改时间均保持一致；
  8 个固定运行依赖身份一致。新实验输入及每个实际输出均与记录哈希一致。
- 独立审查未发现阻塞此只读增量的代码问题；它不替代宿主、接收器、精确变速、
  六份手动验证记录及整曲试听验收。全部相关写入限制继续保留。
