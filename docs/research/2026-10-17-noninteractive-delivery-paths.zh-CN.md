# MIDI → 新 FLP → 后台试听：先调研再实验

2026-10-17。用户要求暂停新的生成／宿主尝试，先比较足够多的可行路径。
本次阶段只读源码、官方文档及既有本地证据；不启动新 DAW、不下载音源／模型、
不上传素材，不把调研中的工具清单或 README 变成兼容性结论。
已启动的单曲 MIDI 任务继续运行，不重启；其完成与音乐质量资格分别记录。

## 选型结论与充分条件

优先保留“已验证的普通参考组件＋原创受限写入器＋官方后台渲染／ZIP 导出”路线。
现成完整后端保留为备选，不能为复用而隐式舍入严格 MIDI 的事件或时钟。
这是结合本机既有成功记录与下述源码差距作出的工程判断，不是外部产品的质量排名。

调研达到可继续实验的条件：已比较直接格式写入、完整转换器、模板编辑库、
宿主命令行、宿主脚本／MCP、独立 MIDI 合成试听六类路径；明确每条入口、许可／
运行环境、已知损失、FL26 证据、最小验证和退出条件；没有尚待核查、可能直接
改变首选方案的接口。不能用仓库数量替代这些条件，也不承诺已经穷尽全部软件。

## 路径对照

| 路径 | 能解决什么 | 不能据此认定什么 | 取舍 |
| --- | --- | --- | --- |
| 现有原创受限参考写入 | 本机已有非截断 960 PPQ、三个独立 3x Osc 通道、九个采样器路由的原生对照；避免更换后端 | 相对样本路径、真实歌曲混合增益、完整新候选独立校验／重开尚未齐全 | 首选，补缺口后再生成歌曲 |
| DawVert 完整转换 | 有 FLP 通道、采样器和 playlist 的实际写入代码，可提取待验证的实现规则 | 其输出端的 PPQ／整数转换和旧版格式不能自动满足严格保真或 FL26 资格 | 只复用有证据的规则；完整后端单独隔离后再评估 |
| PyFLP 模板编辑 | 已有 parse/save 与 note/channel 模型 | 有 save 方法不等于支持新的事件宽度、playlist 布局和宿主播放 | 保留为独立解析／对照备选，避免重复适配 |
| Music2DAW / demixer | 现成后端接口或端到端项目结构 | 本地只读适配不是上游 writer 的写入资格；静音或舍入输出不是可发声保真交付 | 继续沿用已核实边界，不作为零成本替换 |
| FL Studio 官方命令行 | 已有 FLP 的批量音频、MIDI 和 ZIP 导出 | 文档未提供通用的“给 MIDI 和音色配置后无交互保存新 FLP”命令 | 作为生成后的宿主验证通道 |
| 官方 Piano roll / MIDI 脚本及 MCP | 已激活宿主上下文里的音符／控制 API | 文件存在、桥接可连或工具数多，不代表能无键鼠建工程及另存 | 先核对真实调用；带键盘自动化的路径排除 |
| FluidSynth＋SoundFont | 原生 MIDI → WAV 快速文件渲染，可作独立试听对照 | 不生成 FLP，也不验证 FL Studio 实际路由／时序 | 第二备选；需另审 Windows 二进制和音色，不自动安装 |

第三方后端的固定提交、源码入口、许可和具体损失见
[后端逐项核查](2026-10-17-flp-backend-paths.zh-CN.md)。

## 官方宿主通路：有入口，但不等于无界面建工程

官方命令行列出 `/R` 音频渲染、`/E` 格式、`/O` 输出目录、`/D` 诊断默认设置、
`/M` 导出 MIDI 和 `/Z` 导出 ZIP。页面介绍可批量处理工程及 MIDI，但没有说明
可由命令行指定完整音源、导入策略并保存新 FLP。因此，直接喂入 MIDI 仍是待验证
备选，不能把渲染入口当成已证实的建工程接口。
[官方导出说明](https://www.image-line.com/fl-studio-learning/fl-studio-online-manual/html/fformats_save_export.htm)

ZIP 格式包含 FLP 以及 Sampler／Audio Clip 用到的样本；第三方插件内部的样本
不普遍包含。故 `/Z` 可以作为“宿主重新序列化并打包，再提取到新位置重开”的
候选验证步骤。是否可替代本项目的另存验收仍需观察实际新 FLP、引用和重渲染，
不直接等同于 GUI Save As，也不能只凭退出码判定成功。
[官方工程格式](https://www.image-line.com/fl-studio-learning/fl-studio-online-manual/html/fformats_project.htm)

Piano roll API 可操作音符和标记，脚本由 Piano roll 菜单发现；MIDI 脚本是宿主
回调，需要在 MIDI 设置中选择控制器。官方接口说明不能单独证明存在无需配置的
独立 Python 建工程运行时。未发现通用文件名参数保存接口；MIDI 功能表中的保存
动作也不能自动满足独占输出保护。
[Piano roll API](https://www.image-line.com/fl-studio-learning/fl-studio-online-manual/html/pianoroll_scripting_api.htm)、
[MIDI API](https://www.image-line.com/fl-studio-learning/fl-studio-online-manual/html/midi_scripting.htm)

## 已有本机证据与尚缺证据

以下是本地既有实验的限定观察，不是上游文档保证，也不是已发布功能：

- 受限参考的 96 → 960 PPQ 非截断对照，完整 PCM 与原参考一致；截断尾部对照
  存在末段差异，旧裁剪／标记限制不解除。
- 按 DawVert 所示的 built-in sampler 事件作用域规则，省略空插件名／封装记录的
  新参考两次后台渲染正常退出、PCM 相同。不能分别断言其中某一记录就是唯一超时原因。
- 九种不同原创校准音在十二通道参考中的九个时窗分别通过频率核对，两次完整 PCM
  一致。它证明这些校准路由，不能证明真实鼓音色或歌曲质量。
- 三个原创新和弦音同时渲染，与三个独立单音 PCM 相加最大差一个量化单位。
  所测旧 cut 设置与零值结果相同；不能由此泛化所有重叠、切音和多通道情况。
- 增益 1280、相对音频路径、原创鼓采样器在真实歌曲上的长尾和混合仍未验证。
  写入器开发草稿未完成，测试尚未通过、没有接入 CLI 或发布，不作为成功能力。

## 结束调研后仅按顺序验证

1. 等现有 MIDI 任务终态，保留实际结果／失败，不因等待超时重启。重新核对完整
   当前来源和全部音符／时间审计，不通过则停在对应原因。
2. 先通过离线合成测试及独立字节预算校验。优先减少不必要字段修改；增益、复音
   或路径若需改变，分别用小型参考证明，不能直接在真实歌曲上猜测修复。
3. 验证包内样本引用：新位置、中文／空格路径、无旧绝对路径依赖；对照声部时窗、
   混合是否削波和尾部是否截断。每项先固定预期及失败退出条件。
4. 前提齐备才生成本曲的新 FLP 候选；有界后台渲染两次，检查实际完整音频、
   原坐标／声部、输入身份及整个进程树退出，再用新 ZIP／提取／重开验证引用。
5. 提供真实 MIDI 重建试听文件及参考音频，明确未验收项。听验、模型质量、既有
   严格 MIDI、GUI／安装和完整发布资格继续分别阻断，不能用分轨播放代替重建。
6. 补齐测试／文档，最终 head 的独立审查、全部 CI 和当前主线核查后再合并。
   只推送公开源代码、原创测试和文档；全部真实文件及后端只保存在本地。

每个新实验只改变一个已识别问题或一组明确的格式规则；结果不符合预期即停下
定位证据。没有新变量／新证据，不重复相同宿主失败。不得绕过旧 writer 门槛。
