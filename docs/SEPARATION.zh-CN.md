# 完整来源绑定分轨候选与独立重放

这是 M2 的开发入口：读取已独立核验的解码报告，在隔离 CPU 进程中生成四个完整
分轨估计、源时钟 WAV、原始分区输出和未分配残差。再次运行模型、逐项匹配全部
信号后，才签发独立重放回执。它尚未授予音乐质量、共享作业成功或 FLP 写入资格。
最终目标和验收标准见[批准设计](superpowers/specs/2026-10-16-deliverable-audio-to-flp-design.zh-CN.md)
及[交付路线](DELIVERY_ROADMAP.zh-CN.md)；固定模型、许可与依赖差异沿用
[Spleeter 运行环境](SPLEETER_RUNTIME.zh-CN.md)，没有新增或隐式下载依赖。

## 开发入口

先按既有说明显式准备固定的 55 个文件和新的私有后端，再生成当前可验证的整数
PCM WAV 或合格 FLAC/MP3 解码报告。路径仅作示例：

```powershell
uv run suno2flp separate-audio D:\private\decode\decode.json D:\private\spleeter-backend --output D:\private\separation-v1
uv run suno2flp verify-separation D:\private\separation-v1\separation.json --replay-output D:\private\separation-replay-v1
```

所有输出目录必须不存在、父目录必须存在。输出不得与输入、解码依赖、后端、归档、
实现配方或原候选目录重叠；拒绝链接／reparse 路径，保留失败尝试，不覆盖重试。
当前原生配置仅支持 Windows x64、应用 CPython 3.11.16，源采样率 8,000–192,000 Hz、
单／双声道、非空且不超过 600 秒。时钟契约覆盖此范围，600 秒全长资源与产品性能
仍未验收。默认测试不需要 DAW、模型、GPU 或网络；缺少前提明确失败。

`separate-audio` 返回 `inferred_candidate`；`verify-separation` 匹配后返回
`complete_native_replay_matched`。二者都保留 `model_qualification=not_assessed`、
`musical_correctness=not_proven_per_song`、`writer_eligibility=blocked` 和
`execution_allowed=false`。这两个命令没有宿主或写入器路径，也没有接入共享作业。

## 完整时钟、分区和数值规则

令源帧数为 N，源采样率为 Fs，模型采样率为 44,100 Hz。所有长度使用整数向上取整：

| 对象 | 明确规则 |
| --- | --- |
| 模型帧数 M | `ceil(N × 44100 / Fs)` |
| 返回源网格帧数 B | `ceil(M × Fs / 44100)`，源 WAV 保留前 N 帧，另外保存 B−N 帧尾部 |
| 声道 | 单声道显式复制为左右双声道；双声道保留来源顺序，不混音 |
| 原点 | 源第 0 帧对应时间 0；没有音符网格化、源事件平移或速度图替换 |
| 前向重采样 | 已验证 float64 PCM → SciPy polyphase；有理比按最大公约数约分，Kaiser β5、常量零延伸，随后显式转 float32 |
| 反向重采样 | 每轨 float32 模型波形 → 同一 polyphase 配方 → 源采样率 float32 WAV；同率时不滤波 |

分离是模型估计，重采样和 float32 输出也不承诺与源样本无损相等。原始源和完整
float64 解码文件保留；尾部、输入精度转换及每一步的长度和哈希都在候选中可追踪。

分区始终锚定到整首信号的 STFT，而非把若干歌曲片段各自独立加窗再拼接：

- 窗长4096、步长1024、周期 Hann、T512、F1024、零扩展高频 mask，MWF关闭。
- 总 STFT 行数为 `ceil((M+4096)/1024)`；按最多512行顺序分组，包括不满块的结尾。
- 第 k 块起始行 `s=512k`、行数 r，虚拟波形起点 `s×1024−4096`，
  长度 `(r−1)×1024+4096`。超出整首模型波形的输入部分显式填零。
- 原始局部逆变换使用同一 Hann 和固定 `2/3` 系数，不对每块重复进行上游全曲裁剪。
  邻接原始输出重叠3072采样点；仅按全局坐标、固定声部顺序逐块 float32 相加。
  只在整首模型范围裁剪，所有原始块完整保留。
- `vocals`、`drums`、`bass`、`other` 是模型声部标签，不表示已经分对乐器或得到音符。

源网格的残差是 `source − fsum(four estimates)`，单声道源先显式复制。残差保存为
完整双声道 float64 原始数据，并报告峰值及加入残差后的最大守恒误差（上限1e−12）。
没有削波、归一化、增益对齐或隐式延迟补偿。残差代表未分配内容，不是第五种乐器；
守恒正确不能证明分离或转写正确。

## 独立核验、溯源和完成标记

新生成报告使用 `schema_version=2` 和
`source-bound-spleeter-four-stem-candidate-v2`，记录本次全新空原生目录中生成的
`native/keras-cache/keras.json`。`runtime_context` 保留完整文件身份及严格四字段：
`floatx=float32`、`epsilon=1e-7`、`backend=tensorflow`、
`image_data_format=channels_last`。读取限制为64KiB，拒绝缺失、重复键、额外字段和
不支持的设置；独立读取器从当前字节重建设置，并核对完整原生目录的声明成员。
发布前变化或新增文件均阻断。重放还要求配置的全部原始字节一致，不忽略空白差异。
下游来源读取器使用同一字节比较；音高及鼓的调用内已验证证据也冻结 v2 原生目录
成员，在最终复核时拒绝新增文件。它们不把完成凭据当作数值验证的替代。

v1 元数据仍可识别，保持原有未获资格状态；不能补填旧报告，也不能用 v2 过程给 v1
签发新重放凭据。需要在新目录重新生成。修改分离契约会改变后端适配器身份，须从
已有固定归档重新准备一个新的隔离后端；旧后端、候选和失败记录保持原样。
记录配置不授予模型、音乐或宿主资格，不改变任何音频样本或时间换算。

候选保存原音频、完整解码证据、源时钟、当前应用／模型／运行时／配方身份、完整
16,788 项模型负载见证、原生执行证明、请求及 stdout/stderr。新输出包括：

- `native/model-input.f32`、每块输入和四轨原始输出、四个完整模型网格波形；
- `native/<stem>.wav`、每轨完整重采样尾部（为空也保留）；
- `unassigned-residual.f64`、`native/result.json`、完整文件身份清单；
- v2 的 `native/keras-cache/keras.json` 及解析设置；
- 候选 `separation.pending.json` 和成功后独占发布的 `separation.json`。

父进程不导入 NumPy／TensorFlow／SciPy。独立标准库核验器检查所有有限数值、完整
源时钟 WAV 头、每块的精确输入与零填充、按原顺序 float32 重建的全曲波形、完整
残差及其统计。同率时另比对源→模型 float32 转换和模型→源 WAV 的全部样本。
异率的滤波配方经独立标量参考实验检验；每个实际候选另须完整原生重放。

新进程重放比较所有来源／模型语义、原生计算结果，以及每块输入／输出、模型网格、
源 WAV、尾部和残差的全部字节。只排除每次运行自然不同的耗时、内存观察值、日志及
派生输出地址／修改时间；这些仍各自保留并核验。原生执行证明和音乐时钟没有被排除。
耗时最多1800秒、观察到的峰值工作集最多16GiB等契约每次分别检查；这不是硬内存沙箱。
重放结果不一致时保留新候选和诊断，但没有 `replay.json` 成功回执。

重放也必须核验实际序列化的候选文件，不能只核验内存对象后给另一个文件签发回执。
暂存报告、移动到别处的完成报告以及原候选内部的重放目录均被拒绝。即使同步修改
所有原始输出、残差和哈希，静态守恒检查可以通过，完整新进程重放仍会拒绝差异。

报告先独占写入暂存文件，核对序列化字节、全部当前见证与取消状态，再用同目录
独占硬链接发布完成名字。成功时两个名字共享字节，都要保持不可变。文件系统不支持
硬链接时明确失败；不会退回复制或覆盖。最后一次检查失败只留下暂存与原始诊断。
完成标记证明当次核验；下一次消费仍须复核当前文件身份。这是可信本地文件完整性
检查，不是防御恶意同用户并发修改的操作系统隔离。

## 已取得的工程证据与保留限制

以下信号与性能数据是既有 v1 历史工程观察，不自动升级为新版运行配置契约的验收。
v2 需要新的隔离后端、新目录和独立记录；旧证据保留原状态。

原创双声道信号包含1,044,481帧（约23.7秒），跨两个512行分区边界，末块仅1行。
独立完整上游图与分区图最大绝对差分别为人声1.75e−10、鼓3.73e−9、贝斯5.82e−11、
其他2.24e−8，低于实验前固定的1e−5上限。首／边界附近／末尾四个脉冲的实际峰位置
完全一致。该轮分区原生计算约16.34秒、峰值工作集约736MiB；完整图约14.34秒、813MiB。
这是一次小信号观察，不是全曲性能或音乐资格。

另以37帧原创信号测试8k、16k、22.05k、44.1k、48k、96k、192k七种采样率及单双声道，
用独立 sinc／Kaiser／上采样 FIR 标量实现比较正反向滤波、原点和全部额外尾部。
误差上限在执行前固定为2e−6，14组全部通过；原始数据与配方身份留在本地。
一首175秒、48kHz双声道真实歌曲随后完成15个全局分区的来源绑定候选及完整新进程
重放，所有中间／四轨／尾部／残差信号字节一致。原音频及执行源码身份未变，模型
帧数7,717,500，返回源帧数8,400,000；最大守恒误差约2.78e−17，未分配残差峰值约0.10745。
首轮原生计算约39.16秒、观察峰值工作集约998MiB，连同完整独立文件／数值核验的
候选流程约356秒，另一次完整重放核验约513秒。它们是本机单曲工程观察，不能替代
10次稳定性、完整作业性能、分离质量或听感验收。真实素材、身份与原始结果只在本地；
最终提交／审查以对应 PR 为准。

上述记录属于当时的运行证据，不能推出未来逐字节稳定。接通分轨转写时，两次新
全曲重放出现小幅浮点差异并被精确比较拒绝。当前工作进程固定关闭 TensorFlow
remapping，并从实际 Session 配置检查此项；执行契约新增必填
`graph_profile=spleeter4-cpu-no-remapping-v1`，仍固定8个计算线程。短片段跨已测
运行上下文一致只支持这项配置选择，不替代新的全曲和10次稳定性验收。旧后端因
适配器身份变化失效，旧记录缺少策略证据即拒绝；只在新目录重新准备和分离，不能
修改或提升旧报告。无数值容差、裁剪、舍入或时序变化。

可显式重复原生实验：

```powershell

```

忽略目录。所有原素材、基准与旧副本均不修改。仍待完成：分离质量基准和校准、鼓／
节拍／结构分析、分轨到转写的明确来源桥接、推断编排、共享作业、宿主重开／渲染、
