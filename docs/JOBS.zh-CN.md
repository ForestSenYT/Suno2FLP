# GUI／CLI 共用的转换作业基础

M1 已实现 `core.jobs`／`pipeline.jobs` 状态契约，以及独占持久化、真实 PCM 音频
预检和 GUI／CLI 共用的同步作业服务。M2 新增[逐样本保真的 PCM 解码](AUDIO_DECODE.zh-CN.md)。
它们属于[已批准交付路线](DELIVERY_ROADMAP.zh-CN.md)的基础部分；薄 GUI 已接入，
分离、转写、完整转换和宿主 worker 尚未接入。

## 已实现的行为

`new_job(job_id, source_identity, output_directory)` 只读核对源身份并返回新任务。
输出必须是新的、与原输入分离的目录；函数不创建目录或文件。任务固定包含 input、
decode、separate、analyze、transcribe、arrange、route、write、host_verify、quality、
publish 十一个阶段，按顺序开始。这里的阶段名称是作业协议，不是相应 worker 已存在。

`start_stage`、`report_progress`、`finish_stage`、`stop_job`、`resume_job` 返回独立
深拷贝，保留调用者状态和历史。运行中进度为严格整数 0–99，不能回退；100 只在
阶段完成时设置。完成需要非空、唯一、位于作业输出树内且当前身份匹配的产物。
开始／完成阶段和恢复任务时重新核对原输入及所有已完成阶段的产物。

取消、失败或阻断保留已完成阶段和当前尝试。恢复只将中断阶段重置为待执行，
保留旧事件并追加恢复记录。原输入或完成产物改变时不能恢复，但用户仍可以取消
一个输入已变化的运行任务；取消不依赖文件仍可读。

模型保存有序事件历史和状态快照，验证时从事件重建状态，拒绝乱序、缺阶段、
伪造快照、矛盾状态及多余事件负载。服务入口重验可变模型，不直接信任已改动属性。
载入模型也拒绝把输出树指向包含原素材的位置。
创建事件独立保存首次源身份，状态中的源身份必须与其一致；仅更新“当前身份”
不能复用旧阶段。输入改变需建立新作业，而不是替换旧作业的源字段。

## 证据与权限边界

文件身份和事件重建只证明结构及当前文件一致性，不证明某个模型、插件或宿主
真的执行正确。记录可被用户编辑，不是签名证书。后续 runner 必须调用真实适配器、
保存实际结果，再由独立验证器检查质量与宿主输出。

所有任务保持 `host_compatibility=unverified`、`writer_eligibility=blocked`、
`execution_allowed=false`。状态转换函数不启动进程、不写文件、不发送 MIDI，也不能
完成 publish 或设置最终 `succeeded`。即使前十个阶段都声明了匹配产物，最终发布
仍需未来的独立证明契约；这里不能从一组状态布尔值获得写入／交付许可。

## 验证及后续

原创合成测试覆盖完整阶段、严格进度、事件顺序、不可变转换、来源／产物变化、
取消恢复、目录分离和最终成功阻断。测试中的文件是契约身份夹具，不是有效转写
结果或宿主验收证据；原有 MIDI 和写入器行为未改变。

## 持久化和命令

`pipeline.job_store` 每次只追加一个事件到 `states/00000000.json`、
`00000001.json` 等；记录上一个文件的路径、SHA-256、长度和修改时间。
创建以独立源身份为起点，载入时核对完整链并重放状态；不存在可修改的 latest 指针。
写入采用独占创建及 flush/fsync，拒绝过期 head、跳事件、改变来源、乱序、缺失、
重复 JSON 键和非规范文件。半写或损坏的最新文件会阻断，不能跳过并从旧状态继续。
中断文件保留；fsync 不承诺断电时目录项一定已持久化，载入会拒绝不完整链。

在源文件之外选一个尚不存在、父目录已存在的输出目录：

```powershell
suno2flp create-audio-job "C:\Music\song.wav" --output "D:\Jobs\song-v1" --job-id song-v1
suno2flp run-audio-job "D:\Jobs\song-v1\states\00000000.json"
suno2flp verify-audio-job "D:\Jobs\song-v1\states\00000005.json"
```

每条命令输出 JSON，包含 `record.path` 和实际 `job`。后续变更命令应传上一次返回的
最新 `record.path`；示例 00000005 是首次有效 PCM 预检／解码后的阻断记录，重试会追加编号。
创建／核验／取消返回 0；运行因缺少能力阻断返回 3，输入损坏失败返回 1。
创建返回 0 只表示任务记录已保存，核验返回 0 只表示相应证据一致。

`run-audio-job` 实际核对[音频结构](AUDIO_INPUT.zh-CN.md)，独占保存预检报告并完成
input，再将整数样本无损换算到新的 float64 PCM，并独立恢复／比较全部源整数样本。
通过后完成 decode，随后以 `worker_unavailable` 阻断，separate 及之后保持待执行。
报告完整性核验从当前音频独立重算，不能仅通过替换报告及哈希宣称成功。
发生中断的 input／decode 会先记为 `interrupted`，再记录恢复和新尝试；旧候选及报告保留。
解码每次使用新的子目录；旧 M1 历史可以追加这个阶段，已完成产物只在独立复核后复用。
源身份或完成产物改变则拒绝运行／恢复，需建立新任务。

`cancel-audio-job <最新记录>` 可在源文件丢失时取消待执行／运行中的状态。
已阻断、失败或取消的任务已停止，取消命令返回其原记录并保留原因。
服务是同步调用，尚无后台队列或运行进程抢占；并发变更通过独占事件
文件拒绝过期写入。只读历史载入不要求源文件存在，核验和恢复则要求当前证据一致。

[GUI](GUI.zh-CN.md) 在单工作线程中调用同一服务；可选 `should_cancel` 回调在安全边界
请求取消，不需要桌面输入或强杀线程。检查前、预检后、解码及逐样本验证块边界响应请求，
保留历史；当前 I/O／身份哈希仍可能先完成，未完成产物不会宣称完成。音频模型和 FLP／后台宿主适配器仍分别
接受许可、固定版本、质量及宿主证据的门槛约束。
