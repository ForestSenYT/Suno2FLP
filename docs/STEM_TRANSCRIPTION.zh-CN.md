# 估计分轨到音符候选

开发入口把[来源绑定分轨](SEPARATION.zh-CN.md)的 vocals、bass、other 送入固定
[Basic Pitch](BASIC_PITCH.zh-CN.md)。输出仍是未经音乐质量验收的候选，不生成
MIDI／FLP，不完成共享作业，不授予模型、宿主或写入资格。鼓保留为音频，明确标记
`not_transcribed_by_pitched_model`，不会套用旋律模型生成虚假的鼓音符。

## 来源与时钟

原始录音的解码报告与分离估计分别记录。新候选采用
`estimated-stem-basic-pitch-candidate-v1`，其 `source` 同时记录原曲／原始解码、
确切分轨名称及文件、完整分离报告、当前批次实际新运行的分离重放报告与收据。
没有把估计分轨伪装成原始音频解码，也没有改变既有 MIDI 或原始转写 v1 的语义。

分离输出为原采样率、原 N 个采样帧的双声道 float32。准备阶段只将每个有限样本
精确扩展为 float64，包含负零和非正规数；不归一化、不限幅、不转整数、不重采样、
不移动帧或交换声道。独立验证器使用整数 IEEE 指数／尾数运算推导目标位模式，
不复用生产者的浮点转换。只接受当前分离器的完整 58 字节标准头；非有限值、
损坏头、长度不符、额外尾部及不支持的时钟明确失败。

随后模型沿用原有 22050Hz 重采样、完整窗口／有效行归属和原曲坐标关系；扩展
样本格式不会改变任何时间原点。原始预测、音符、重叠弯音及未经校准的激活均保留。
`other` 仍是混合声部，不能声称已分出独立乐器；人声音符也不等于歌声重建。

## 运行与复核

已有当前解码、完整分离候选及固定本地运行时后：

```powershell
uv run suno2flp transcribe-stems D:\private\separation\separation.json --backend D:\private\basic-pitch --output D:\private\new-stem-batch
uv run suno2flp verify-stem-transcription D:\private\new-stem-batch\stem-transcription.json --output D:\private\new-full-replay
```

命令默认处理 vocals／bass／other。Python 接口可显式选择按这个顺序排列的非空
唯一子集；重复、倒序、未知声部和 drums 均在运行前拒绝。首次准备模型仍使用已有
显式准备入口，无下载或全局安装。源代码配方变化要求新的当前后端记录，不能把
历史候选或冻结实验直接升级成当前证据。共享契约还可能被两个后端同时记录；
本次实际旧分离输入即因 `core/transcription.py` 身份变化被正确拒绝。此时须在
新目录准备当前分离后端、从原始解码重新生成分离候选，不能编辑历史摘要来通过。

每批先在自己的新目录重跑完整分离并比较全部证据，再逐声部准备／推理。不能提供
一个自称成功的收据跳过实际模型重放。薄批次报告仅保存有界的完整报告身份；读取
时重新打开完整分离／声部报告和全部依赖，不截断或重复嵌入庞大模型清单。

完整批重放再次运行分离和每个声部的推理，对比全部样本、预测、音符、弯音及
语义配置。路径／每次运行的资源观察分别保留。重新计算声明哈希不能代替新推理。
临时报告、异地复制的完成报告、输入／输出重叠、当前依赖变化均拒绝。
最终完成名使用已有的独占暂存验证与硬链接发布；失败／取消保留新尝试诊断，不
修改旧记录，不留下该批完成标记。已完成的个别声部不代表整批完成。

同一次受控调用已经完整核验的数值关系，随后通过不可变的预期文件身份守卫其
有效性。每次消费和发布仍重新读取全部文件哈希、模型目录成员及运行时元数据；
调用方修改声明或重算哈希不能改写已捕获的预期值。不会在每次发布重复重建相同的
波形和预测。此守卫不序列化、不跨调用复用，也不从收据布尔值获取数值或模型资格。
首次读取未受信批次仍做完整独立数值核验；完整重放仍实际重新运行模型。

## 验证与保留限制

默认测试使用原创微小波形、真实文件／解码／来源验证，只替换原生模型进程边界。
外部测试需显式提供私有完整分离报告和当前 Basic Pitch 后端，默认跳过；不要求
CI 下载模型或运行 DAW。真实单曲无逐音符真值时，不能报告音乐 F1 或准确率。

首轮175秒私有曲诊断在模型准备后1832秒仍只有人声候选完成，整批及重放未完成，
因此协作取消并保留全部文件。原始输入和当时源码身份复核未变；该次有并行检查和
CPU候选运行，不构成发布性能基准。后续减少重复核验，完整真实重放仍为独立门槛，
以实际记录为准，不能由合成测试或 CI 代替。

后续两次完整分轨重放发现浮点字节不一致，流程正确拒绝发布整批，原输入及执行
源码身份均未改变。短片段在同一进程内可重复，但原始／实际执行计算图和恢复权重
相同时，运行上下文仍可能改变融合内核的结果。关闭 TensorFlow remapping 后，
已观察的不同导入／预处理上下文及各三次预测逐字节一致；这支持固定运行策略，
不构成完整根因证明或全曲稳定性承诺。新执行证据必须声明
`graph_profile=spleeter4-cpu-no-remapping-v1`，保持8个计算线程和原有全部精确比较。
旧后端／分离证据不能补写这个字段，必须在新目录重新准备并完成实际重放；完整
单曲、性能和音乐质量验收仍需独立结果。所有失败及诊断副本保留在本地。
