# FL26 六个实验副本：手动宿主验证清单

本清单仅准备人工实验，不操作电脑、不运行写入器，也不解除任何写入限制。
六个副本的宿主打开、缩放、另存、重开和试听结果目前全部为
`pending_not_performed`。每个副本使用一份[空白结果表](templates/FL26_HOST_RESULT.zh-CN.md)。
填写后的记录、截图、工程和读取报告只留本地，不加入 PR。

## 文件与实验范围

现有实验根目录为 `D:\Git\Suno2FLP\.tools\fl26-clip-write-validation-v1`：

- `probes/`：六个既有字节实验副本，只读使用，不能覆盖。
- `baseline.json`、`probe-provenance.json`：原始身份、差异预算和来源记录，只读保留。
- `manual-validation-v1/`：本次准备的本地索引、六份待填表和准备核验记录。
- `host/manual-v1/<副本名>/`：人工实验时才创建的另存目录；本轮没有创建 FLP。

原始 `templates/user-minimal.flp`、正音符基准和三个 GUI 对照均不参与编辑。
实验副本是从基准派生的受控字节修改，**不是生产写入器的成功输出**。
已有文件名一律不覆盖；重复实验用新的 `manual-v2/` 等目录，另建记录，保留上一轮。

本轮“缩放”分成两个独立观察：

1. **视图缩放**：放大 Playlist/Piano roll，只为了读取位置；音乐位置、长度和音符应不变。
2. **片段长度实验**：固定左边缘，仅拖动 Playlist 片段右边缘，将已确认长度从 L 改为 2L。
   这不是音符时间缩放或 PPQ 转换。普通边缘调整模式无法确认时，记为 `blocked`。

不要拉伸音符、修改速度/PPQ、移动左边缘、补画音符或修补数据来获得预期画面。
本清单不验证任意时间拉伸，也不为 `0x8000` 等标记位推断通用语义。

## 每份副本按此顺序执行

开始前复制空白表或使用本地已准备表。先填写操作者、时间和运行编号。
核对本机完整版本为 **26.1.7 build 5654**；其他版本的结果单独记录，不能填入本轮。
不要在已有歌曲中实验。若当前工程有未保存工作，先自行妥善保存。

### 0. 身份与保护检查

- [ ] 用本地准备记录核对输入的完整路径、SHA-256、大小及修改时间，确认对应的副本名。
- [ ] 重新核对五个受保护工程和六个副本的身份；保留新核对记录，不覆盖既有清单。
- [ ] 为本份准备新的 `host/manual-v1/<副本名>/` 目录，确认两个目标文件均不存在：
  `01-no-edit-save.flp`（A）、`02-right-edge-2x-save.flp`（B）。存在则换新运行目录。
- [ ] 截图和结果也放在本次本地目录，记录相对路径及采集时间。暂未执行的格子保持未勾选。

### 1. 打开输入，只观察

- [ ] 记录 Playlist 的轨道、片段开始/长度/结束，以及 Piano roll 两音符的音高、位置、
  长度、力度、Slide 状态；保留界面原文、单位和画面证据。

  阶段，记失败或阻断原因，不接受修复、替换或覆盖来凑出“通过”。

## 如何填写结论

每阶段状态仅选：`pending_not_performed`（默认）、`pass_observed`（该阶段实际观察满足
条件）、`fail_observed`（已观察到偏差）、`blocked`（前置条件不满足）或 `skipped`（写明原因）。
空白/未知值表示没有事实，不能自动转为通过；采集时间、原始截图/文字、文件身份和回读
报告要能相互定位。单阶段通过不代表整份通过，视图通过也不代表裁剪或播放通过。

结果表将 GUI 观察、实际试听、只读字节比较和待研究项分开。六份即使都得到一致结果，
仍须独立审查才能形成范围明确的兼容性证据；这些人工记录不被运行时作为写入授权读取。
`writer_crop`、`writer_clip_attributes` 及未知事件、依赖、溯源和完整性门槛保持原样阻断。
不能据此运行生产写入器、修改白名单或把旧计划改成可执行状态。

只向 PR 提交本清单和空白模板。填写后的工程、哈希/原始字段报告、截图和六份本地结果
均不上传。现有证据与限制见[离线回归说明](FL26_CLIP_OFFLINE.md)和
[字段对照](FL26_FIELD_EVIDENCE.md)。
